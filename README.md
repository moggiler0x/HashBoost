# HashBoost

Десктопное приложение для автоматического андервольтинга, разгона и оптимизации доходности видеокарт в реальном времени с учётом стоимости электроэнергии.

HashBoost работает как надстройка над майнером (SRBMiner-MULTI, Rigel / PeakMiner и другими с JSON API). Вместо ручного подбора частот в MSI Afterburner программа сама проводит серию замеров для каждой карты на конкретном алгоритме и находит точку **максимальной чистой прибыли**, а не максимального хешрейта: там, где дальнейший разгон приносит меньше денег, чем сжигает электричества.

![Дашборд](docs/screenshots/dashboard.png)

## Возможности

| Модуль | Что делает |
|---|---|
| **Smart Auto-Tune** | Пошагово меняет частоту ядра (curve lock), памяти и напряжение через NVML (NVIDIA) и ADL (AMD), ждёт стабилизации хешрейта и фиксирует замеры |
| **Profit-per-Watt Engine** | Тариф за кВт·ч, КПД блока питания, потребление платформы, доходность монеты (вручную или по API) → доход, расходы на свет и чистая прибыль в сутки и месяц |
| **Интеграция с майнерами** | Телеметрия по локальному API: текущий и средний хешрейт, принятые / отклонённые / устаревшие шары, аппаратные ошибки |
| **Health Monitor** | Температуры GPU, HotSpot и VRAM, кулеры, потребление каждой карты и рига |
| **Watchdog** | При ошибках вычислений откатывает карту на последние стабильные настройки, при отвале перезапускает майнер, при перегреве снижает лимит мощности |
| **Менеджер профилей** | Лучший пресет для каждой карты под каждый алгоритм, переключение в один клик |

## Как работает калибровка

1. **Базовый замер** на стоковых настройках: хешрейт, потребление, прибыль.
2. **Частота ядра.** Частота фиксируется (curve lock) и сдвигается грубым шагом вниз от стока, пока растёт чистая прибыль; если снижение не помогает, проверяется разгон вверх. Затем лучшая точка уточняется мелким шагом (по умолчанию 15 МГц).
3. **Частота памяти.** Смещение вверх, пока растёт прибыль и нет ошибок; если выигрыша нет, проверяется снижение (для алгоритмов, зависящих от ядра, это экономит ватты).
4. **Андервольтинг.** При зафиксированной частоте напряжение снижается до порога нестабильности (сначала крупно, потом шагом 10 мВ), затем возвращается на запас надёжности (по умолчанию +20 мВ).
5. **Проверка.** Длинный замер итоговых настроек. Если появились ошибки, добавляется ещё запас.
6. **Сохранение профиля** индивидуально для карты (учёт «кремниевой лотереи») и алгоритма.

### Мульти-калибровка: самая выгодная монета для каждой карты

В Лаборатории выберите режим **«Все монеты — найти самую выгодную»**. Карта по очереди калибруется на каждом алгоритме из калькулятора (сейчас Poseidon2 / Quantus и PearlHash / Pearl), после чего программа сравнивает чистую прибыль и сохраняет профили под каждую монету. Карты, которые алгоритм не тянут (например, RX 570 на PearlHash), пропускаются.

Это важно, потому что выгоднее всего бывает разная монета: PearlHash считается на тензорных ядрах, поэтому RTX 4060 даёт на нём 65 TH/s и при московском тарифе зарабатывает на нём почти вдвое больше чистыми, чем на Quantus, а GTX 1660 SUPER без тензорных ядер выдаёт всего 1 TH/s и на Quantus выгоднее в разы.

После калибровки всех карт риг переводится на монету с максимальной суммарной прибылью, а в логе указывается, каким картам выгоднее другая монета. Чтобы майнер переключался сам, во вкладке **Настройки** укажите путь к майнеру и аргументы для каждой монеты (по строке: `poseidon2: --algorithm poseidon2 ...`).

Каждый шаг: применить настройки → прогрев (20 с) → замер в течение окна стабилизации (90 с по умолчанию, настраивается). Шаг считается нестабильным при аппаратных ошибках, отвале карты, перегреве, пропаже API майнера, росте отклонённых шар или проседании хешрейта. После нестабильного шага настройки сразу откатываются на последний стабильный, при отвале майнер перезапускается.

![Лаборатория](docs/screenshots/lab.png)

### Андервольт на NVIDIA

NVML не даёт задавать напряжение напрямую, поэтому используется тот же приём, что и curve lock в Afterburner: частота ядра фиксируется через `nvmlDeviceSetGpuLockedClocks`, а V/F-кривая поднимается положительным смещением (`nvmlDeviceSetGpcClkVfOffset`). Карта держит ту же частоту на меньшем напряжении. Смещение напряжения в мВ переводится в смещение кривой коэффициентом `tuning.nvidia_mhz_per_mv` (по умолчанию 1,2 МГц на мВ).

## Установка и запуск

Нужен Python от 3.10 до 3.14.

```bash
pip install -e .
hashboost                 # обычный запуск
hashboost --simulate      # симулятор рига: RTX 4060, GTX 1650, 2× GTX 1660 SUPER, RX 570
```

Изменение частот и напряжений требует прав администратора (Windows) или root (Linux). Без них программа покажет телеметрию, но применить настройки не сможет.

Если видеокарты не найдены, HashBoost сам переходит в режим симуляции. В симуляции время ускорено в 30 раз (`--time-scale`), так что полная калибровка карты занимает пару минут вместо 40–50.

### macOS (экспериментально, только симуляция)

На Mac нет драйверов для управления видеокартами, поэтому HashBoost всегда запускается в режиме симуляции. Это удобно, чтобы владелец рига сначала посмотрел, как работают калибровка, калькулятор розетки и профили, а потом поставил программу на сам риг.

Запуск одной командой из папки проекта в терминале:

```bash
bash scripts/HashBoost-mac.command
```

Или дважды кликните этот файл в Finder (если macOS не даёт его открыть, нажмите правой кнопкой и выберите «Открыть»).

Больше ничего ставить вручную не нужно. При первом запуске скрипт сам найдёт подходящий Python 3.10–3.14, при необходимости поставит Python 3.13 (через Homebrew или [uv](https://docs.astral.sh/uv/)), соберёт окружение `.venv` и запустит программу. Это занимает пару минут, следующие запуски происходят сразу. Если окружение сломано или собрано не той версией Python (например, 3.15, под которую ещё нет сборок numpy и Qt), скрипт пересоздаст его сам.

Настройки и профили на Mac хранятся в `~/Library/Application Support/HashBoost`. Сохранённые в симуляции профили привязаны к виртуальным картам и на реальный риг не переносятся.

Калибровка без интерфейса:

```bash
hashboost --tune 0 --algorithm poseidon2
```

## Настройка майнера

Во вкладке **Настройки** выберите тип майнера и адрес API.

| Майнер | Как включить API | Адрес по умолчанию |
|---|---|---|
| SRBMiner-MULTI | `--api-enable --api-port 21550` | `http://127.0.0.1:21550` |
| Rigel / PeakMiner | `--api-bind 127.0.0.1:5000` | `http://127.0.0.1:5000` |
| Другой | любой JSON API, пути к полям задаются в `miner.json_map` | — |

Если указать путь к исполняемому файлу майнера, HashBoost будет сам запускать и перезапускать его. Если оставить пустым, майнер запускается вручную, а программа только читает его API.

Пример `json_map` для произвольного майнера:

```json
{"gpus": "devices", "index": "id", "hashrate": "speed", "accepted": "shares.ok",
 "rejected": "shares.bad", "invalid": "hw", "algorithm": "algo"}
```

## Калькулятор розетки

![Калькулятор](docs/screenshots/calc.png)

* **Однотарифный и двухтарифный счётчик.** Для двухтарифного задаются цены дня и ночи и часы ночной зоны (по умолчанию 23:00–07:00). Расход на свет при работе 24/7 считается по средней цене, а отдельно показывается, сколько риг заработает, если майнить только ночью. Есть пресеты тарифов Москвы с 01.10.2026: квартира с газовой плитой (8,90 ₽; день 10,64 / ночь 4,85), с электроплитой (8,46; 10,11 / 4,61), сельские н.п. и СНТ (8,28; 9,90 / 4,51).
* **Самая выгодная монета и окупаемость.** Для каждой карты таблица показывает лучшую монету, чистую прибыль на ней и на других монетах, цену карты и срок окупаемости (цена / чистая прибыль в сутки). До калибровки используются типичные цифры модели из рейтинга Kryptex, после калибровки — замеры именно вашей карты. Цена карты по умолчанию берётся из рейтинга Kryptex по курсу доллара, её можно исправить прямо в таблице.
* **Доходность монеты** задаётся как доход в валюте за сутки с единицы хешрейта (₽ за 1 MH/s для Quantus, ₽ за 1 TH/s для Pearl). Её можно подтягивать по API: укажите URL, который отдаёт JSON, и путь к числу в ответе (например, `data.0.revenue`).

### Откуда взяты цифры

| Что | Значение | Источник |
|---|---|---|
| Доходность Quantus (qtc) | 0,3067 ₽/сут за 1 MH/s | выплаты Kryptex 5.10.7 на реальных ригах 25.10.2026: GTX 1660 SUPER 138,02 MH/s → 1269,87 ₽/мес, GTX 1650 102,32 MH/s → 941,39 ₽/мес |
| Доходность Pearl (prl) | 2,0142 ₽/сут за 1 TH/s | там же: RTX 4060 61,56 TH/s → 3719,92 ₽/мес |
| Хешрейт, потребление, цена и окупаемость карт | `hashboost/core/market.py` | рейтинг «Лучшие видеокарты для майнинга» Kryptex, обновлён 23.10.2026 |
| Тарифы | см. выше | распоряжение по тарифам Москвы, действуют с 01.10.2026 |
| Курс доллара | 80,54 ₽ | ЦБ РФ на 24.10.2026 |

Комиссия пула по умолчанию 0 %: Kryptex показывает доход уже за вычетом своей комиссии. Доходность меняется вместе с курсом монет и сложностью сети, поэтому её стоит периодически обновлять (вручную или по API).

Симулятор повторяет эти риги: хешрейт карт на стоке совпадает со справочником Kryptex, а GTX 1660 SUPER на реальных настройках (1500 / 6801 МГц) выдаёт те же 138 MH/s при ~70 Вт, что и в PeakMiner.

## Где хранятся данные

| ОС | Папка |
|---|---|
| Windows | `%APPDATA%\HashBoost` |
| macOS | `~/Library/Application Support/HashBoost` |
| Linux | `~/.config/hashboost` |

Там лежат `config.json` (настройки), `profiles.json` (профили) и `hashboost.log`. Папку можно переопределить переменной окружения `HASHBOOST_HOME`.

## Структура проекта

```
hashboost/
  hardware/      драйверы: NVML (NVIDIA), ADL OverdriveN (AMD), симулятор рига
  miners/        клиенты API: SRBMiner, Rigel/PeakMiner, универсальный JSON; управление процессом
  core/
    profit.py    расчёт дохода, расходов (одно- и двухтарифный счётчик), окупаемости и лучшей точки
    autotune.py  цикл калибровки
    multitune.py мульти-калибровка по нескольким монетам
    market.py    справочник карт по данным Kryptex
    advisor.py   самая выгодная монета для каждой карты и срок окупаемости
    watchdog.py  Health Monitor и Watchdog
    profiles.py  хранение профилей
    runtime.py   опрос телеметрии и связка модулей
  gui/           PySide6: дашборд, калькулятор, лаборатория, профили, настройки
tests/           тесты ядра на симуляторе
```

## Ограничения текущей версии

* AMD поддерживается через ADL OverdriveN (Polaris / Vega, например RX 570). Для RDNA (RX 5000+) нужен Overdrive8, он в планах.
* Форматы API майнеров разобраны по документации и терпимы к отсутствию полей, но на реальных версиях их стоит сверить. При расхождении можно переключиться на универсальный JSON-клиент.
* Калибровка идёт по одной карте за раз (остальные продолжают майнить).
* Весь риг майнит одну монету: майнер запускается один. Если картам выгодны разные монеты, программа это покажет, но для майнинга разных монет одновременно нужен отдельный майнер на каждую группу карт (в планах).
* Готового установщика (.exe) пока нет.
